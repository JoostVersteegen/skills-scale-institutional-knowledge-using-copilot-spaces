# OctoAcme Project Management Docs

This README is the entry point to OctoAcme's project management guidance. The documents below cover the project lifecycle, team roles, delivery practices, and continuous improvement.

## Process summary

OctoAcme uses a lightweight, iterative project lifecycle:

1. **Initiate** — validate the business need, define measurable outcomes, identify stakeholders, and decide whether to proceed.
2. **Plan** — turn approved work into a prioritized backlog, agree on acceptance criteria and the Definition of Done, estimate work, and map milestones, risks, and dependencies.
3. **Execute and track** — deliver in small increments using the project board and pull request workflow; test and review work, monitor progress and metrics, and escalate blockers.
4. **Release** — confirm acceptance criteria, CI and security checks, release notes, and rollback plans; deploy, verify, and communicate the release.
5. **Reflect and improve** — hold retrospectives after sprints, releases, milestones, or incidents, then track a small set of actionable improvements.

Project Managers coordinate delivery, risks, schedules, and communications; Product Managers own outcomes and priorities; developers and QA collaborate to build and validate changes; stakeholders provide input and approvals. Teams maintain shared artifacts such as the project one-pager, backlog, risk register, release plan, and retrospective actions, adapting meeting cadence to the project.
