# OctoAcme Project Management Docs

This directory contains the project management and delivery knowledge for OctoAcme. The docs are designed to standardize how the team initiates, plans, executes, communicates, ships, and improves work across projects.

## Overview

- [octoacme-project-management-overview.md](./octoacme-project-management-overview.md) — high-level overview of roles, lifecycle, artifacts, and communication cadence
- [octoacme-project-initiation.md](./octoacme-project-initiation.md) — how to validate and authorize a new project or initiative
- [octoacme-project-planning.md](./octoacme-project-planning.md) — backlog, milestones, dependencies, and delivery planning
- [octoacme-execution-and-tracking.md](./octoacme-execution-and-tracking.md) — day-to-day execution, tracking, quality gates, and blockers
- [octoacme-risks-and-communication.md](./octoacme-risks-and-communication.md) — risk management, stakeholder communication, and escalation
- [octoacme-release-and-deployment.md](./octoacme-release-and-deployment.md) — release process, deployment checklist, rollback playbook
- [octoacme-retrospective-and-continuous-improvement.md](./octoacme-retrospective-and-continuous-improvement.md) — retrospective structure and ongoing improvement loop
- [octoacme-roles-and-personas.md](./octoacme-roles-and-personas.md) — shared role definitions and responsibilities

## How to use these docs

Use the overview as the starting point, then move into the specific guide that matches the phase of work. Keep the docs updated in the repository so they stay a single source of truth for project practices and team expectations.

## Process improvement

If you want to propose a change to any of these process docs, use the issue template in `.github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml`.
